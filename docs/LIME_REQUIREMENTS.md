# LIME / eBarimt POS API — шаардагдах материал ба хариу ирүүлэх загвар

> **Хэнд:** LIME (eBarimt POS API 3.0 instance нийлүүлэгч)
> **Хэнээс:** msgbill.mn — Message Billing Service (Медиа Профессионал ХХК)
> **Зорилго:** Платформын түвшинд болон шинэ мерчант бүр дээр LIME талаас
> шаардагдах зүйлс, хариу мэдээллийн нэг мөр форматыг тогтоох.

---

## 1. Суурь мэдээлэл

**msgbill.mn** нь нэхэмжлэх → төлбөр → **eBarimt (НӨАТ-ын баримт) автомат**
олголт хийдэг B2B платформ. Баримтыг ТЕГ-ийн **POS API 3.0** стандартаар,
LIME-ийн суулгасан локал instance-ээр дамжуулан үүсгэдэг. Мерчант бүр
**өөрийн ТТД (merchantTin), өөрийн posNo-оор** баримт олгоно — платформын
нэрээр биш.

| Талбар | Утга |
|---|---|
| Платформ | https://msgbill.mn (Медиа Профессионал ХХК) |
| POS API instance | `https://vat.onlime.mn` (одоо ажиллаж буй) |
| Холбоо барих | stemuujin@gmail.com |

## 2. Платформын түвшинд НЭГ УДАА шаардагдах зүйлс

| # | Материал | Тайлбар | Статус |
|---|---|---|---|
| 1 | POS API 3.0 instance хандалт | `VAT_BASE_URL` — `GET /rest/info` 200 буцаадаг байх | ✅ бэлэн (vat.onlime.mn) |
| 2 | Instance-ийн үндсэн posNo | Баримт илгээхэд ашиглагдана | ✅ бэлэн |
| 3 | Операторын эрх (ТЕГ) | `saveOprMerchants` API түлхүүр + операторын POS дугаар (Posapi@itc.gov.mn-ээс) — мерчантыг ТЕГ-т бидний зүгээс бүртгүүлэх боломж | ✅ тохируулагдсан |
| 4 | ТЕГ нэгдсэн нэвтрэлт (OIDC, client_id=vatps) | Операторын токен авахад | ✅ тохируулагдсан |
| 5 | Instance-ийн засвар/шинэчлэлтийн мэдэгдэл | Төлөвлөгөөт зогсолтыг урьдчилан мэдэгдэх суваг | 🔲 тохирох |
| 6 | Support SLA | Ажлын цагаар холбогдох хүн/суваг, хариу өгөх хугацаа | 🔲 тохирох |

## 3. ШИНЭ МЕРЧАНТ бүрд шаардагдах зүйлс

### 3.1 Урьдчилсан нөхцөл (мерчант өөрөө хийнэ — бид зааварчилна)

1. Байгууллага ТЕГ-т POS-оор бүртгүүлсэн байх;
2. e-invoice.ebarimt.mn / ТЕГ порталдаа нэвтэрч операторын хүсэлтийг
   зөвшөөрөх.

### 3.2 Бидний илгээх хүсэлт

Системээс LIME-ийн бүртгэлийн имэйл рүү автоматаар очно:

```
Гарчиг: [msgbill.mn] Шинэ мерчант бүртгүүлэх хүсэлт — <Байгууллагын нэр>

  Байгууллагын нэр:  <нэр>
  Регистр:           <регистрийн дугаар>
  Хаяг:              <хаяг>
  Утас:              <утас>
  Имэйл:             <имэйл>
  Merchant TIN:      <ТТД — мэдэгдэж байвал>
```

### 3.3 Таны буцаан ирүүлэх зүйлс (ГОЛ ХЭСЭГ)

Мерчантыг instance дээр нэммэгц тухайн имэйлд **хариу болгон (Reply)** дараах
форматаар ирүүлнэ үү:

```
Гарчиг: RE: [msgbill.mn] Шинэ мерчант бүртгүүлэх хүсэлт — <Байгууллагын нэр>

Байгууллага:      <нэр>
Регистр:          <регистр>
merchantTin:      <ТТД>
posNo:            <олгогдсон POS дугаар(ууд)>
branchNo:         <салбарын код, ж: 001>
Instance:         https://vat.onlime.mn
Бүртгэсэн огноо:  <YYYY-MM-DD>
Тэмдэглэл:        <анхаарах зүйл байвал>
```

| Талбар | Бидний хэрэглээ |
|---|---|
| `merchantTin` | Баримт бүр тухайн байгууллагын ТТД-ээр олгогдоно |
| `posNo` | Баримт илгээх POS — олон бол мерчант нэгийг сонгоно |
| `branchNo` | Баримтын салбарын код |

> Бид `GET /rest/info`-оос posNo/branchNo-г автоматаар татдаг тул бүртгэл
> хийгдмэгц мэдэгдэхэд л хангалттай — гэхдээ дээрх хариу нь тулгалт болно.

### 3.4 Бидний талын баталгаажуулалт

```
GET https://vat.onlime.mn/rest/info   → merchantTin жагсаалтад шинэ ТТД харагдана
Тест баримт (1₮) → ebarimt.mn дээр гарч буйг шалгана
```

## 4. Ажиллагааны горим

- Баримт үүсэхгүй байсан ч төлбөр алдагдахгүй — баримт **PENDING** төлөвт
  орж, 10 минут тутам автоматаар дахин илгээгдэнэ (instance түр унтарсан
  үед ч мөн адил).
- Сугалааны дугаар/QR-ийг ТЕГ-ийн журмын дагуу хугацаатай хадгалж устгадаг.
- Асуудал гарвал бид instance-ийн статус (`/rest/info`), баримтын алдааны
  бүртгэлтэйгээ хамт хандана — тодорхой лог өгч чадна.

## 5. Хүсэлт

1. §2-ын 5, 6-р мөрийн (мэдэгдлийн суваг, SLA) тохиролцоог баталгаажуулах;
2. Мерчант бүртгэлийн хариуг §3.3 форматаар ирүүлж хэвшүүлэх;
3. Instance-ийн хувилбар шинэчлэгдэх (POS API breaking change) бол 14+
   хоногийн өмнө мэдэгдэх.
