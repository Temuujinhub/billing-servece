# Bonum Gateway — мерчант онбордингийн журам ба хариу ирүүлэх загвар

> **Хэнд:** Bonum Gateway (sales@bonum.mn)
> **Хэнээс:** msgbill.mn — Message Billing Service (Медиа Профессионал ХХК)
> **Зорилго:** Манай платформоор дамжуулан төлбөр хүлээн авах байгууллага бүрд
> терминал нээх, хариу мэдээллийг НЭГ МӨР форматаар солилцох журмыг тогтоох.

---

## 1. Платформын танилцуулга

**msgbill.mn (Message Billing Service)** нь Монголын байгууллагуудад зориулсан
нэхэмжлэх/төлбөр хураалтын B2B SaaS платформ. Байгууллага Excel эсвэл API-аар
нэхэмжлэх үүсгэж, төлөгч бүрт SMS-ээр төлбөрийн линк очиж, төлөгч Bonum
Gateway-ийн хуудсаар (QR/банкны апп) төлнө. Төлбөр тус бүрийн орлого **тухайн
байгууллагын өөрийн дансанд** шууд ордог тул байгууллага бүр Bonum дээр
**өөрийн терминалтай** байх шаардлагатай.

| Талбар | Утга |
|---|---|
| Платформ | https://msgbill.mn |
| Оператор компани | Медиа Профессионал ХХК |
| Холбоо барих | stemuujin@gmail.com |

## 2. Бидний илгээх хүсэлт (терминал нээлгэх)

Шинэ байгууллага бүртгүүлэхэд манай системээс **sales@bonum.mn** хаяг руу
дараах бүтэцтэй имэйл автоматаар очно:

```
Гарчиг: [msgbill.mn] Шинэ мерчант бүртгүүлэх хүсэлт — <Байгууллагын нэр>

  Байгууллагын нэр:  <нэр>
  Регистр:           <регистрийн дугаар>
  Хаяг:              <хаяг>
  Утас:              <утас>
  Имэйл:             <имэйл>
  Банк:              <банкны нэр>
  Дансны дугаар:     <орлого хүлээн авах данс>
  Дансны нэр:        <дансны эзэмшигчийн нэр>

WEBHOOK URL (терминалд бүртгэнэ үү): https://msgbill.mn/api/v1/webhooks/bonum/callback
```

## 3. Таны буцаан ирүүлэх 3 зүйл (ГОЛ ХЭСЭГ)

Терминал үүсмэгц дор дурдсан **3 утгыг** тухайн хүсэлтийн имэйлд **хариу
болгон (Reply)** ирүүлнэ үү. Бид эдгээрийг (1) нэхэмжлэх/төлбөрийн линк
үүсгэх, (2) төлбөр орсныг webhook-оор баталгаажуулах, (3) төлбөрийн төлөв
лавлахад ашиглана.

| # | Талбар | Бидний систем дэх нэр | Хэрэглээ |
|---|---|---|---|
| 1 | **Terminal ID** | `BONUM_TERMINAL_ID` | Нэхэмжлэх (invoice/линк) үүсгэх, төлөв лавлах хүсэлтийн иж бүрдэл |
| 2 | **Secret Key** (App Secret) | `BONUM_APP_SECRET` | API нэвтрэлтийн токен авах |
| 3 | **MERCHANT_CHECKSUM_KEY** | `BONUM_CHECKSUM_KEY` | Webhook-ийн `x-checksum-v2` (HMAC-SHA256) гарын үсгийг шалгаж төлбөрийг баталгаажуулах |

**Хариуны загвар** — яг энэ форматаар (мөр бүр `Талбар: утга`) ирүүлбэл
бүртгэл хамгийн хурдан хийгдэнэ:

```
Гарчиг: RE: [msgbill.mn] Шинэ мерчант бүртгүүлэх хүсэлт — <Байгууллагын нэр>

Байгууллага:            <нэр>            (бидний илгээсэнтэй ижил)
Регистр:                <регистр>
TERMINAL_ID:            <терминалын дугаар>
SECRET_KEY:             <secret key>
MERCHANT_CHECKSUM_KEY:  <checksum key>
Орчин:                  production | test
Webhook бүртгэгдсэн:    тийм | үгүй   (https://msgbill.mn/api/v1/webhooks/bonum/callback)
```

⚠ **Заавал хийгдэх:** терминал бүрд webhook хаягийг
`https://msgbill.mn/api/v1/webhooks/bonum/callback` гэж бүртгэнэ үү —
үгүй бол төлбөрийн мэдэгдэл бидэнд бодит цагаар ирэхгүй.

## 4. Бид эдгээрийг хэрхэн ашиглах вэ

```
Нэхэмжлэх үүсгэх:  POST /invoices  (TERMINAL_ID + SECRET_KEY-ээр токен авч)
                    → төлөгчид Bonum checkout линк
Төлбөр орох:       Bonum → манай webhook (x-checksum-v2 = HMAC-SHA256(body,
                    MERCHANT_CHECKSUM_KEY)) → гарын үсэг таарвал баталгаажна
Давхар шалгалт:    invoice-check API-гаар төлөв лавлаж ledger-т бичнэ
```

- Нууцуудыг манай системд **AES-256-GCM шифрлэлттэй** хадгална, UI дээр
  дахин ил харагдахгүй, лог/repo-д хэзээ ч бичигдэхгүй.
- Нэг байгууллагын нууц нөгөөд хэрэглэгдэхгүй — терминал бүр өөрийн
  байгууллагадаа тусгаарлагдана.

## 5. Аюулгүй дамжуулалтын хүсэлт

Боломжтой бол нууцуудыг имэйлийн биед шууд бус, нэг удаагийн линк
(one-time secret) эсвэл утсаар/өөр сувгаар хуваан ирүүлэхийг дэмжинэ.
Имэйлээр ирүүлсэн тохиолдолд бид бүртгэсний дараа имэйлээ устгана.
