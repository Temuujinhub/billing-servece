# Partner API — туршилтын заавар (Postman)

Гаднын систем (Үйлчилгээ 2, 3, 4) холбохын өмнө **серверт ямар ч дарамт,
бохирдолгүйгээр** туршиж үзэх зориулалттай тест горим байгаа.

## Тест түлхүүр гэж юу вэ

- Dashboard → **Developers** хуудаснаас түлхүүр үүсгэхдээ «Тест түлхүүр»
  сонголтыг чагтална → `bsk_test_...` угтвартай түлхүүр гарна.
- Тест түлхүүрээр хийсэн хүсэлт **өгөгдлийн санд юу ч бичихгүй**, SMS
  илгээхгүй, eBarimt үүсгэхгүй, төлбөр тооцохгүй.
- Хүсэлтийн бүтэц бүрэн шалгагдаж (валидаци бодитойгоор ажиллана), бодит
  хэлбэртэй хариу буцна — хариунд `"test": true` талбар байгаагаар нь ялгана.
- Бодит ажиллагаанд шилжихдээ live түлхүүр (`bsk_...`) үүсгэж солино —
  кодонд өөр өөрчлөлт хэрэггүй.

## Postman-аар турших

1. Postman collection татах: Dashboard → Developers → «Postman collection»
   (эсвэл `https://msgbill.mn/billingservice-partner-api.postman_collection.json`).
2. Collection variables:
   - `baseUrl` = `https://msgbill.mn/api/v1`
   - `apiKey` = өөрийн `bsk_test_...` түлхүүр
3. Хүсэлтүүдийг дарааллаар нь ажиллуулж хариуг харна.

## Эрхийн хүрээ (scopes)

Түлхүүр үүсгэхдээ хэрэгтэй эрхээ сонгоно:

| Scope | Үйлчилгээ | Endpoint |
|---|---|---|
| `invoice` | Үйлчилгээ 2 — API нэхэмжлэх + SMS | `POST/GET /partner/invoices` |
| `receipt` | Үйлчилгээ 3 — eBarimt API | `POST /partner/receipts` (device_id-гүй) |
| `pos` | Үйлчилгээ 4 — POS терминал | `POST /partner/receipts` (device_id-тэй) |

Scope сонгоогүй (хоосон) түлхүүр бүх эрхтэй.

## Idempotency (давхар илгээлтийн хамгаалалт)

POST хүсэлт бүрд `Idempotency-Key` header дамжуулахыг зөвлөнө (өөрийн
системийн захиалгын/баримтын дугаар). Сүлжээний алдаанаас болж хүсэлт
давтагдвал давхар нэхэмжлэх/баримт үүсэхгүй — эхний хариу буцна. Ижил
түлхүүрийг ӨӨР агуулгатай хүсэлтэд ашиглавал `409 IDEMPOTENCY_MISMATCH`.

## Түгээмэл алдаанууд

| Код | Утга | Арга хэмжээ |
|---|---|---|
| `API_KEY_REQUIRED` / `API_KEY_INVALID` | Түлхүүр дутуу/буруу | `X-Api-Key` header шалгах |
| `SCOPE_REQUIRED` | Түлхүүрт эрх алга | Шаардлагатай scope-той шинэ түлхүүр үүсгэх |
| `MODULE_DISABLED` | Үйлчилгээ идэвхгүй | Billing хуудаснаас идэвхжүүлэх |
| `RECEIPT_QUOTA_EXCEEDED` | Сарын шатлалын хязгаар дүүрсэн | Billing → eBarimt API шатлал ахиулах |
| `TERMINAL_BLOCKED` | Терминал блоклогдсон | Billing → POS терминал хэсгээс идэвхжүүлэх |
| `IDEMPOTENCY_MISMATCH` | Түлхүүр давхар өөр агуулгад | Шинэ Idempotency-Key ашиглах |

## Live горимд шилжихийн өмнө

1. Байгууллагын онбординг бүрэн (ТЕГ бүртгэл, eBarimt холболт — ONBOARDING.md).
2. Billing хуудсанд хэрэглэх үйлчилгээгээ идэвхжүүлсэн (шатлал сонгосон).
3. Live түлхүүр үүсгэж, тест түлхүүрээ хүчингүй болгосон.
4. Webhook хэрэгтэй бол Developers → Webhooks (payment.succeeded,
   receipt.created — HMAC гарын үсэгтэй).
